# Релизы и обновления LapisLauncher

## Модель обновления

- Версия приложения берётся из `apps/launcher/package.json` и следует SemVer: `MAJOR.MINOR.PATCH`.
- В production launcher делает **одну** проверку обновления после открытия главного окна. Фонового таймера нет.
- При наличии версии новее текущей справа от «Серверы» появляется «Доступно обновление».
- Скачивание начинается только после нажатия пользователя. После загрузки появляется действие перезапуска для установки.
- Установка блокируется, пока работает Minecraft. На Windows используется NSIS и стандартная проверка цифровой подписи обновления через `electron-updater`.

## Настройка канала

Перед production-сборкой укажите HTTPS-каталог с релизами в `apps/launcher/resources/update-config.json`:

```json
{
  "url": "https://updates.example.com/LapisLauncher"
}
```

Этот URL должен быть доступен только по HTTPS. В него публикуются файлы одного канала: `latest.yml`, NSIS-инсталлятор `LapisLauncher-Setup-<version>.exe` и его `.blockmap`. Не размещайте в этом каталоге секреты, токены или пользовательские файлы.

Для CI вместо изменения файла допустима переменная окружения `LAPIS_UPDATE_URL`; она имеет приоритет во время работы launcher.

## Сборка Windows-релиза

1. Поднимите версию в `apps/launcher/package.json`.
2. Подпишите Windows-приложение сертификатом Code Signing. В CI задайте `CSC_LINK` и `CSC_KEY_PASSWORD` как защищённые секреты.
3. Выполните из корня:

```powershell
pnpm package:win
```

4. Загрузите содержимое `apps/launcher/release` в настроенный HTTPS-каталог одним атомарным выпуском: сначала инсталлятор и `.blockmap`, затем `latest.yml`.

Не изменяйте уже опубликованные артефакты одной и той же версии. Откат выполняется публикацией новой версии с исправлением.
